measurement campaign · 4 GPUs × FlashBoot off/on × 3 images

Where a cold start's time goes, and what placement costs

The same three images are re-pointed at each GPU pool in turn, ten cold starts per cell spread over four six-hour slots a day. A cell's median therefore mixes two things: how long the scheduler took to find a host and get the image onto it, and how long the engine took to boot once it ran. The emberserve images report that split from inside the worker; worker-vllm does not.

Median cold start per cell

Rows are GPU pools, columns the image and FlashBoot setting; the number is the cell's median delay before the job ran (queue + placement + pull + boot), darker is slower, log-scaled. Hover for the spread and the number of cold starts behind it.

Where the seconds go: placement + pull vs engine boot

emberserve cells only (the handler writes a timeline). Each bar is a cell's median split: the seconds from submit until the container existed on a host — scheduling, image pull, create — and the seconds the engine then took to be ready. Baking the weights in makes the second part short and the first part long: a 27 GB image is rarely cached where the scheduler lands.
